# CR-M9-01 — Active/Inactive Record Filter

## Change Request Information
**Change Request ID:** CR-M9-01
**Maintenance Type:** Perfective Maintenance
**Target Version:** 1.1.0
**Priority:** High

## Problem / Opportunity
The current Event Management System allows users to add, edit, delete, and search registration records, but it does not provide a way to filter records based on their Active or Inactive status. As the number of registration records increases, users may have difficulty viewing only the records that are currently active or inactive.

## Desired Outcome
Add an **Active/Inactive record filter** to the Registration Management interface. Users should be able to select whether they want to view all records, only Active records, or only Inactive records while preserving the existing CRUD, search, validation, delete confirmation, persistence, and responsive behavior.

## Acceptance Criteria
1. The system provides a filter that allows the user to select **All, Active, or Inactive** records.
2. Selecting **Active** displays only records with an Active status, while selecting **Inactive** displays only records with an Inactive status.
3. Selecting **All** displays both Active and Inactive records.
4. Existing CRUD, search, validation, delete confirmation, and localStorage persistence continue to work correctly.
5. The filter remains usable on both desktop and mobile screen sizes.

## Priority and Rationale
**High Priority** — The filter improves record management and makes it easier for users to locate and manage registrations as the number of records increases. It is a focused improvement that can be implemented without replacing the existing architecture.

## Affected Areas
* **RegistrationList.vue** — filter interface and filtered record display
* **App.vue** — record status/filter state and data flow, if needed
* **localStorage data** — record status handling and compatibility with existing records
* **User Interface** — addition of the Active/Inactive filter
* **Automated Tests** — new regression tests for the filtering behavior
* **Manual Test Plan** — additional test cases for Active/Inactive filtering
